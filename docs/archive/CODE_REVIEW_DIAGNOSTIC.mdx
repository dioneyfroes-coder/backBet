# Diagnóstico de Revisão de Código

Visão consolidada do estado atual do repositório (nov/2025), pontos fortes e pendências prioritárias para manter qualidade, segurança e rastreabilidade.

## 1. Estrutura e Organização

**👍 Já consolidado**
- DDD modular: `src/core` (domínios), `src/infrastructure`, `src/shared`.
- Controllers + DTOs + rotas coesos (`infrastructure/api/**`).
- Documentação viva em `docs/` cobre arquitetura, módulos, API, observabilidade.

**⚠️ Observações**
- Garantir que novos módulos sigam a convenção `application/use-cases` (evitar typos antigos como `application`).
- Cobertura de docs: manter apenas arquivos relevantes (as referências legadas foram limpas; revisar periodicamente se novos “notes” surgirem fora do padrão).

## 2. Dependências

**Estado atual**
-- Stack em uso: Express 5, Zod, ioredis, mongoose (opcional), (provedor de identidade opcional), Jest, ESLint flat config.
- NestJS/TypeORM/class-validator removidos em favor de implementações próprias.

**Checklist**
- [ ] Rodar `npm outdated` a cada release para atualizar libs críticas (express-rate-limit, helmet, SDKs de provedor de identidade) => impacto: méd.
- [ ] Automatizar `npm audit` no CI (alto).
- [ ] Validar se pacotes dev-only (`tsx`, `tsc-alias`, `@types/*`) não vazaram para runtime (baixo).

## 3. Código & Imports

- `tsconfig.json` já expõe aliases (`@/core/*`, `@/infrastructure/*`, etc.).
- Linter impede `../..` exagerado; reforçar em PRs.
- Circular deps não detectados.

**Ações**
- [ ] Rodar `npm run lint` em cada PR (CI). (alto)
- [ ] Adicionar regra eslint `no-restricted-imports` para uso obrigatório de aliases. (méd)

## 4. Segurança

| Item | Situação | Ação |
|------|----------|------|
| Identidade externa obrig. em prod | ✅ `ApiServer` bloqueia boot sem as variáveis de provedor de identidade quando configurado | Revisar `.env.example` se novas variáveis surgirem |
| Rate limiting | ✅ Global + rotas críticas (`createRouteRateLimiter`) | Monitorar limites por ambiente |
| Input validation | ✅ Zod DTOs em controllers | Cobrir novos DTOs imediatamente |
| Secrets | ✅ `.env` no `.gitignore`; config centralizada (`shared/config`) | Validar Git hooks/CI para impedir vazamento |
| Headers | ✅ helmet + HSTS opcional | auditar CSP ao adicionar novas UIs |

## 5. Observabilidade & Operação

- Snapshots internos (cache/resiliência/dependências), health/readiness/cache endpoints, request context + logging JSON.
- OTEL tracing configurável via `TRACING_ENABLED` + `OTEL_EXPORTER_OTLP_ENDPOINT`.
- Documentação em `docs/OBSERVABILITY.mdx` e dashboards versionados.

**Ações**
- [ ] Propagar snapshots para PM2 WebUI/alertas antes do go-live (alto).
- [ ] Adicionar testes que validem `X-Request-ID` e `requestContext` (méd).

## 6. Typescript & Qualidade

- `tsconfig.json` com `strict: true`; CI roda `npm run build` para validar tipos.
- Cobertura atual: 97%+ (statements/fns/lines) com Jest + SWC.

**Ações**
- [ ] Manter badge de cobertura atualizado no README (baixo).
- [ ] Acompanhar gaps de branches (&lt;90%) nos relatórios e priorizar módulos com menor cobertura (finance/bets). (méd)

## 7. Testes e CI

- `npm run test -- --coverage` cobre auth, wallets, bets, observabilidade.
- Seminda pipeline GitHub Actions: build + lint + test.

**Próximas melhorias**
- [ ] Adicionar suíte de carga (k6/Artillery) para `/auth`, `/wallets`, `/bets`. (méd)
- [ ] Automatizar smoke (`curl /health`, `/health/cache`, `/readiness`) pós-deploy. (méd)

## 8. Backlog de revisão (prioridade)

| Prioridade | Item | Status | Notas |
|------------|------|--------|-------|
| 🔴 Alta | Garantir CI obrigatório (lint/test/build) em todos os PRs | pendente | Bloqueia regressões silenciosas |
| 🔴 Alta | Verificar secrets no CI (variáveis do provedor de identidade, JWT, Redis) antes do deploy | pendente | Use scanners ou validação manual |
| 🟠 Média | Criar webhook do provedor de identidade (user.updated) para sync automático quando aplicável | pendente | Reduz drift entre provedor e domínio |
| 🟠 Média | Tests E2E com provedor de identidade real + cache ligado | pendente | Simula produção |
| 🟢 Baixa | Monitorar duplicação de docs legacy | contínuo | já limpo, manter triagem |

## 9. Recomendações gerais

1. **Revisões enxutas**: validar diffs por domínio (auth/user/wallet/bet) e exigir descrição de testes executados.
2. **Logs**: nunca logar tokens; revisar PRs que toquem `loggingMiddleware`/`requestContext`.
3. **Observabilidade**: qualquer rota nova deve atualizar os snapshots relevantes (latência/contadores internos) e incluir `requestId` no log.
4. **Docs**: atualizar `docs/*.mdx` no mesmo PR da mudança (arquitetura, API, quickstart, observabilidade, integração de identidade, etc.).
5. **Dependências externas**: toda integração (Redis, Mongo, provedores de identidade, OTLP) precisa de fallback documentado + feature flag.
