## Aceite final (Go / No-Go)

- **Veredito: GO condicionado.** O produto está pronto para **homologação** e demonstração — não para movimentar dinheiro real antes das pendências regulatórias.
- Condições que seguem em aberto (bloqueiam produção real):
  1. Validação do build Docker/CI em ambiente com Docker (2 itens finais do DoD);
  2. Provedores reais W-01..W-05 (KYC, geolocalização, SIGAP, PSP, certificação) — ver `docs/SIGAP_CONFORMIDADE.mdx`.
- **Sem essa validação, não há retrocesso**: certificação não é tratada retroativamente com o sistema já movimentando dinheiro.

## Decisão comercial (Fase 36)

> **Vender o BackBet como plataforma/backend de gestão de apostas para operadores autorizados (B2B)** — não operar uma bet própria (B2C).

- **Modelo A (operar uma bet)**: exige autorização SPA, capital regulatório, certificação, KYC/AML, pagamentos, marketing, atendimento e risco financeiro — um **projeto separado de compliance**, não uma etapa de código.
- **Modelo B (B2B)**: o produto **já existe** neste repositório (API `/api/v1` estável, cascata de provedores plugáveis: pagamento/KYC/SIGAP/geolocalização/device). O operador arca com as obrigações regulatórias.

### Evidências vendáveis (testáveis no repo)

Dinheiro exato sem float (`*Cents` + FI-01..FI-10), sem double-spending em saques (idempotência + máquina de estados), concorrência controlada na carteira (`WalletConcurrency.test.ts` — 100 saques), exposição/liability centralizada (`risk`), settlement idempotente (`ReconcileTreasury`), auditoria/retenção, backup/DR (RPO/RTO), segurança de acesso, compliance plugável, reporte SIGAP, jogo responsável, API documentada/versionada, infraestrutura containerizada.

### Dívidas de produto para o B2B (decisão futura)

Multi-tenant (hoje single-operador) · onboarding de operadores · white label/skins · SLA acordado · documentação de integração para operadores. São **evoluções de produto**, não pendências do MVP.

### Alternativa em escopo

Se não houver intenção comercial real: BackBet como **projeto de portfólio** + open source de terceiros em paralelo — cada decisão crítica (double-spending, concorrência, idempotência, transações Mongo, consistência wallet↔bet, disaster recovery) vira material de entrevista.

### Checklist de decisão

- [ ] v1.0 consolidada (técnica) ✅
- [ ] Escolher **B2B** ou **portfólio + open source** (decisão do mantenedor)
- [ ] Se B2B: regulação nacional como **projeto separado de compliance** (SPA, SIGAP, certificação)
- [ ] Toda funcionalidade nova avaliada como **produto**, não como desculpa para expandir o projeto
