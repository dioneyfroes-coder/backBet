# Secrets — Fase 26

> Regra máxima: **nenhum segredo no Git.** `.env` é ignorado; o
> `.env.example` só contém **exemplos seguros** (sem valor real).

## Catálogo de segredos

Formato exigido pelo plano: `nome | descrição | exemplo seguro | obrigatoriedade`.

| Variável | Descrição | Exemplo seguro | Obrigatório? |
|---|---|---|---|
| `JWT_SECRET` | Assina tokens JWT | `openssl rand -hex 32` (colado no `.env`) | **Sim, sempre** (env.ts lança sem ele) |
| `MONGODB_URI` | Conexão do app ao server02 (embute usuário/senha) | `mongodb://backbet:TROQUE_AQUI@192.168.0.20:27017/backbet?authSource=admin&replicaSet=rs0` | **Sim em produção** (env.ts) |
| `REDIS_URL` | Conexão ao Redis | `redis://user:TROQUE@localhost:6379` | **Sim em produção** (env.ts) |
| `MONGO_ROOT_PASSWORD` | Senha do admin do Mongo (server02) | `TROQUE_AQUI_SENHA_FORTE` | Sim (compose server02) |
| `MONGODB_APP_PASSWORD` | Senha do usuário `readWrite` da app | `TROQUE_AQUI_SENHA_APP` | Sim (compose server02) |
| `MAILER_SMTP_URL` | URL SMTP completa do worker de contato | `smtps://usuario:TROQUE@smtp.example.com:465` | Não (sem valor → `jsonTransport`) |
| `SMTP_PASSWORD` | Senha SMTP do health monitor | `TROQUE_AQUI_SENHA` | Só com `OBS_ENABLE_EMAIL_ALERTS=true` |
| `SMTP_USERNAME` | Usuário SMTP do health monitor | `TROQUE_AQUI_USUARIO` | Idem |
| `GF_ADMIN_PASSWORD` | Admin do Grafana (observabilidade) | `TROQUE_AQUI_SENHA_FORTE` | Só ao usar `docker-compose.observability.yml` |
| `PM2_WEB_PASSWORD` | Autenticação da WebUI do PM2 | `TROQUE_AQUI_SENHA_FORTE` | Não (default inseguro `change-me-now`) |
| `OTEL_EXPORTER_OTLP_HEADERS` | Credenciais do collector OTLP | `api-key=TROQUE` | Só com tracing remoto |
| `PAYMENT_PROVIDER_KEY` / `PIX_PROVIDER_KEY` | Chaves do PSP (integração futura, hoje `PIX_PROVIDER=mock`) | `TROQUE_AQUI` (comentado no exemplo) | Só quando houver PSP real |

## Como o código protege

`src/shared/config/env.ts`:

- Carrega `.env` no boot e **lança erro** se `JWT_SECRET` estiver ausente (sempre) e
  se `MONGODB_URI`/`REDIS_URL` faltarem em produção;
- Nunca loga valores — o snapshot de boot expõe só `hasJwtSecret: boolean`;
- credenciais de URLs precisam de percent-encoding (`@` → `%40`, etc.).

## Guard de CI: `npm run check:secrets`

`scripts/check-secrets.cjs` varre **apenas os arquivos rastreados pelo Git**
(`git ls-files`) e falha (exit ≠ 0) se encontrar:

- nomes de arquivo sensíveis (`.env*`, `.pem`, `.key`, `credentials`…);
- chaves AWS (`AKIA…`), chaves privadas, JWTs, chaves Stripe, tokens do GitHub;
- URLs `smtp(s)://usuário:senha@` e `mongodb://usuário:senha@` com credencial real.

Já está no pipeline: `npm run check` (`check:secrets && lint && coverage && build`).
Rode local isolado:

```bash
npm run check:secrets
```

## Como manter segredos fora do Git

- `cp .env.example .env` e preencha — `.env`/`.env.*` estão no `.gitignore`;
- nunca edite `.env.example` com valor real; ele é o único arquivo `.env*` versionado;
- dumps de backup (`docs/BACKUP_RECOVERY.mdx`) guardam dados de usuários e credenciais
  escolhidas — trate `/backups/**` como segredo fora do repositório;
- evite originar segredos em código/comentários; logs devem seguir
  `docs/LOGS.mdx` (sem dados sensíveis).

## Secret managers (produção)

O MVP roda com variáveis de ambiente protegidas (`.env` + compose `env_file`),
o que atende a fase 26. Quando houver operação real, recomendado trocar para:

- **Doppler** ou **1Password CLI**: injeta as vars no `docker compose`
  (`doppler run -- docker compose ...`) sem arquivo `.env` em disco;
- **Hashicorp Vault / AWS Secrets Manager**: lidas no entrypoint
  (`scripts/entry.cjs`) e injetadas só em runtime.

A mudança não altera o código: `env.ts` continua lendo `process.env`.

## Rotação

- `JWT_SECRET`, `MONGODB_URI`, SMTP e chaves de PSP devem ter rotação planejada;
- após rotacionar, reinicie API + workers (config é lida no boot);
- credenciais de banco rotacionadas exigem atualizar também o backup/restore
  (`docs/BACKUP_RECOVERY.mdx`).
