# Finanças e Invariantes Financeiros

Documenta o módulo `src/core/finance` + tesouraria + **invariantes FI-01..FI-10** (especificação formal que nunca pode ser violada).

## Princípios

- **Dinheiro em centavos inteiros**: todo valor interno é inteiro (`Money`, `BetAmount`); a API expõe reais. Nada de `float` em fluxo de valor.
- **Idempotência**: `POST /api/v1/wallets/deposit`, `/withdraw`, `/bets` e `/bets/:id/cancel` aceitam `Idempotency-Key` e respondem `Idempotency-Replayed: true` em replay. Ledger usa `transactionId = <type>:<referenceId>` para tornar o replay inofensivo.
- **Locking otimista**: carteiras usam `version`; escrita obsoleta → `409 CONFLICT`. Retry transitório com backoff exponencial (`retryTransient.ts`) em `WalletService.run()`/`BetService.placeBet()`.
- **Transações Mongo** (replica set `rs0`): wallet/ledger/bet/treasury atomizados.

## Carteira e contas

| Endpoint | Descrição |
|----------|-----------|
| `GET /api/v1/wallets/me` | Saldo, saldo bloqueado e moeda |
| `POST /api/v1/wallets/deposit` | Depósito síncrono (crédito imediato) |
| `POST /api/v1/wallets/deposit/pix-charge` | Charge Pix **PENDING** (QR EMV com CRC16) — **sem crédito imediato** |
| `POST /api/v1/webhooks/pix` | Webhook público (HMAC `X-BackBet-Signature`): `PIX_PAID` credita, `PIX_REFUNDED` estorna, `PIX_CANCELED` ignora; exige `PIX_WEBHOOK_ENABLED=true` |
| `POST /api/v1/wallets/withdraw` | Request de saque (vai para fila Bull; débito definitivo só na conclusão) |
| `GET /api/v1/wallets/history` | Extrato paginado |

Rate limits específicos: `WALLET_*_RATE_LIMIT_*`.

## Saques (workflow)

Estados da solicitação: `REQUESTED → VALIDATING → APPROVED → PROCESSING → COMPLETED | FAILED`. O valor fica em `lockedBalance` durante todo o processamento — nunca some antes da confirmação do payout. O débito definitivo usa `transactionId = WITHDRAWAL_COMPLETED:<requestId>` (idempotência do ledger proíbe pagamento duplo, mesmo com retry do worker ou resposta duplicada do provedor). Provedor hoje: `PIX_PROVIDER=mock`.

## Tesouraria

- `HouseWallet` concentra ganhos/perdas do operador; `HouseTreasuryService` + `ReconcileTreasury` detectam divergências sem corrigir silenciosamente.
- Relatório diário (admin): `GET /api/v1/admin/reports/daily-financial-summary?date=YYYY-MM-DD&currency=BRL` — depósitos, saques, apostas, GGR, tesouraria, saques/apostas pendentes e exposição.

## Matriz de cenários críticos

Cobertura de testes por cenário (carteira/aposta/settlement/withdrawal/PIX/SIGAP) com status e local de validação: `docs/TESTING-ENV.mdx` (matriz consolidada).

## Invariantes FI-01..FI-10

Suite principal: `src/core/finance/domain/services/__tests__/FinancialInvariants.test.ts` (pura de domínio, repositórios in-memory, roda em ms: `npx jest FinancialInvariants`).

| # | Enunciado | Garantido por | Testado em |
|---|-----------|---------------|------------|
| **FI-01** | `Wallet.balanceCents >= 0` sempre | `Wallet.withdraw`/`lock` rejeitam débito acima do saldo; `Money.subtract` rejeita negativo; lock otimista | FI-01; `WalletConcurrency.test.ts` (100 saques) |
| **FI-02** | `Wallet.lockedBalanceCents >= 0` sempre | `Wallet.unlock`/`withdrawLocked` rejeitam valores acima do bloqueado | FI-02 |
| **FI-03** | Exposição de risco nunca é negativa | `RiskProfile.decreaseExposure` satura em 0; reservas atômicas só aumentam | FI-03 |
| **FI-04** | Um saque nunca paga duas vezes | Máquina de estados (`completePayout` só de `PROCESSING` → `COMPLETED`) + `transactionId = WITHDRAWAL_COMPLETED:<id>` + `lockedBalance` no hold | FI-04 |
| **FI-05** | Uma aposta nunca é liquidada duas vezes | `Bet.resolve` valida `status === PENDING` (`BET_NOT_PENDING`) | FI-05 |
| **FI-06** | Um `transactionId` nunca é reutilizado para movimentos diferentes | Esquema `<type>:<referenceId>`; ledger append-only com `transactionId` único | FI-06 |
| **FI-07** | Uma `Idempotency-Key` não muda de operação | `IdempotencyService.resolveExistingMeta` compara fingerprints → `409` | FI-07 |
| **FI-08** | WIN gera exatamente um crédito `BET_WIN` | Fluxo único em `BetService.resolveBet` + guard `BET_WIN:<betId>` + estado terminal | FI-08 |
| **FI-09** | CANCEL gera exatamente um reembolso `BET_REFUND` | Fluxo único em `BetService.cancelBet` + guard `BET_REFUND:<betId>` | FI-09 |
| **FI-10** | LOSS não gera prêmio | Ramo `if (result === 'WON')` exclusivo em `BetService.resolveBet` | FI-10 |

> **Nota de estado (21/09/2026)**: todos os FI-01..FI-10 passam (`npm test` verde); **0 falhas** conhecidas na suíte (1094 testes passando). O FI-05 (aposta nunca liquidada duas vezes) é coberto por `FinancialInvariants.test.ts` e reforçado pelos testes de replay/integração.
