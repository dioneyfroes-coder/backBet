## Endurecimento do servidor

Nos dois hosts Ubuntu, **antes** de subir a aplicação:

```bash
# server01 (API + proxy + workers)
sudo bash deploy/harden-server.sh                      # HOST_ROLE=web

# server02 (MongoDB) — libera 27017 apenas para o server01
sudo HOST_ROLE=db SERVER01_IP=192.168.0.10 bash deploy/harden-server.sh
```

O script é idempotente e **se recusa a desabilitar senha SSH** enquanto não
existir chave pública instalada (evita travar o acesso). Recomendações extras:

- usuário administrativo com `sudo`, nunca `root` direto;
- `ufw status verbose` e `ssh -i <chave> usuario@<ip>` testados em nova sessão
  antes de fechar a atual;
- `fail2ban` opcional para o SSH (o script avisa se ausente).

## Logs sem segredos

- `src/shared/config/env.ts` loga somente `hasJwtSecret: boolean`, nunca o valor;
- nenhum `console.*` deve emitir `process.env.<SEGREDO>`; adicione uma entrada
  no revisão de PR se aparecer;
- política completa em `docs/LOGS.mdx`.

## Verificação operacional (pós-deploy)

```bash
npm run check:secrets                          # sem segredos no Git
npm run audit:prod:critical                    # 0 críticas em produção
curl -sf https://$PUBLIC_DOMAIN/health         # HTTPS + Caddy ok
curl -sfI https://$PUBLIC_DOMAIN/ | grep -i strict-transport-security
ufw status verbose                             # só 22, 80, 443 (+ 27017 s/ server01)
npm run backup:drill                           # ciclo de recuperação ok
```
