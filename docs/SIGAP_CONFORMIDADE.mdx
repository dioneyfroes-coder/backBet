# SIGAP, Conformidade e Certificação

Este documento une dois blocos regulatórios do BackBet:

1. **Módulo SIGAP** (`src/core/sigap`) — transmissão de remessas à SPA (Secretaria de Prêmios e Apostas, Ministério da Fazenda) com ciclo determinístico **ACK/REJECT → retry → auditoria**.
2. **Preparação para certificação** — matriz de controles que a SPA exige, mapeada para **evidências objetivas no repositório**, verificável por máquina.

## SIGAP — transmissão regulatória

### Objetivo

Reportar apostas/eventos à SPA de forma confiável: cada remessa é transmitida via adapter, persistida com estado definitivo (**ACKED | REJECTED | FAILED | IMPEDED**) e auditada — nunca dependendo de logs para comprovar a submissão.

### Arquitetura

| Camada | Peça |
|--------|------|
| Domínio | `SigapService`, entidade de transmissão, `ISigapTransmissionPort` |
| Aplicação | use cases de transmitir/consultar impedimento |
| Infra | `SigapTransmissionJob` (job periódico), `MockSigapTransmissionProvider` (dev/test), `SigapTransmissionRepository` |
| Config | `appConfig.sigap` (`provider`, `enabled`, `retryMaxAttempts`), env `SIGAP_ENABLED`, `SIGAP_RETRY_MAX_ATTEMPTS` (default **5**) |

O adapter real (mTLS/TLS 1.2, e-CNPJ, Bearer token, endpoints SPA/Serpro) é **plugável** pelo contrato `appConfig.sigap.provider` — o código não muda, só a implementação e o ambiente de homologação SPA.

### Ciclo de transmissão

```text
SigapTransmissionJob → SigapService → adapter (mock hoje) → transmissão
   → ACKED (ackId)                                persistido + auditoria
   → REJECTED (errorCode/errorMessage)  → retry (teto SIGAP_RETRY_MAX_ATTEMPTS)
   → FAILED (falha de transmissão)      → retry
   → esgotado                            → SIGAP_RETRY_LIMIT_EXCEEDED (métrica)
```

- Reenvio idempotente por `(operatorId, fileType, referenceDate)` — não duplica remessa (incrementa `attemptCount`).
- REJECTED após o teto incrementa `backbet_sigap_submission_rejected_total`.
- Impedimento (`checkImpediment`): `IMPEDED` / `NOT_IMPEDED` / `UNKNOWN` (sem provider).
- Ações admin de transmit/impediment registram **auditoria**.

### Matriz de cobertura (S1-S7)

| # | Cenário | Status |
|---|---------|--------|
| S1 | Transmissão registrada como **ACKED** com `ackId` | **Coberto** (`SigapService.test.ts` + `admin.sigap.integration.test.ts`) |
| S2 | Reenvio idempotente por chave não duplica remessa | **Coberto** |
| S3 | SPA **REJECT** persistido com `errorCode`/`errorMessage` | **Coberto** |
| S4 | Falha marca **FAILED** e nova tentativa reenvia | **Coberto** |
| S5 | Retry com teto: `SIGAP_RETRY_LIMIT_EXCEEDED` após `retryMaxAttempts` | **Coberto** |
| S6 | Impedimento `IMPEDED`/`NOT_IMPEDED`/`UNKNOWN` | **Coberto** |
| S7 | Ações admin registram auditoria | **Coberto** |

### Configuração

| Variável | Padrão | Descrição |
|---|---|---|
| `SIGAP_ENABLED` | `false` | Liga o job de transmissão |
| `SIGAP_RETRY_MAX_ATTEMPTS` | `5` | Teto de tentativas de transmissão |
| `SIGAP_PROVIDER` | `mock` | Adapter (`mock` hoje; real com credenciais SPA) |

## Preparação para certificação (SPA)

O que pode ser feito **em desenvolvimento** sem operador autorizado ou certificação formal é **verificável por máquina**:

```bash
npm run security:assess
```

O script varre o repositório, confere cada controle contra a evidência (arquivo, configuração ou código) e escreve o relatório em `reports/security-assessment-<timestamp>.txt` (e `.json`). Sai com código 1 se algum controle **bloqueante** falhar (mesmo espírito do `check:secrets`).

O controle **F-04** (exposição de MongoDB/Redis) é sensível a contexto: `SECURITY_CONTEXT=lab` permite bind em interface **privada** (ex.: `192.168.22.250:27018`/`:6379`), enquanto `SECURITY_CONTEXT=prod` bloqueia qualquer publicação desses serviços. Sem a variável, o contexto é derivado de `BACKBET_RUNTIME_ENV`/`NODE_ENV` (`production` ⇒ PROD, senão LAB). A decisão considera o **bind address** de cada porta, não apenas a presença de `ports:` — bind wildcard (`0.0.0.0`) é sempre reprovado.

### Matriz de controles → evidência (PASS)

**A — Segurança de acesso**: JWT obrigatório, guarda ADMIN, bcrypt custo 12, rate limit global/por rota, helmet, CORS por allowlist, payload limit `10mb`, validação Zod, `check:secrets` no CI. **Tudo PASS** com evidência em `AuthMiddleware.ts`, `adminRoutes.ts`, `ApiServer.ts` (101/131/136/157), `BaseController.ts`.

**B — Auditoria, logs e retenção**: eventos persistidos (`AuditEventSchema`), retenção ≥ 5 anos (`AUDIT_RETENTION_DAYS=1825`), ledger append-only (`LedgerEntrySchema` índice único), política de logs sem segredos. **PASS**.

**C — Continuidade de negócio**: `backup:create/validate/restore/drill` + runbook de DR com RPO/RTO (`docs/BACKUP_RECOVERY.mdx`). **PASS**.

**D — Integridade financeira**: dinheiro em centavos, invariantes FI-01..FI-10 testados, limites min/max de depósito/saque (`MoneySecurityService`), reconciliação (`GetDailyFinancialSummary`/`ReconcileTreasury`). **PASS**.

**E — Compliance modular**: ports de KYC, geolocalização e integridade de dispositivo com gate no saque; módulo SIGAP; jogo responsável (`ResponsibleGamblingService`). **PASS**.

**F — Infraestrutura de produção**: imagem Docker + compose, hardening (`deploy/harden-server.sh`), TLS (`deploy/proxy/Caddyfile`), serviços internos sem porta pública, CI com gates de segurança, observabilidade/alertas. **PASS**.

### Pendências que dependem de terceiros (PEND)

Não bloqueiam o ambiente de dev, mas são **pré-requisito para dinheiro real**:

| ID | Pendência | Ação externa |
|----|-----------|--------------|
| W-01 | Provedor real de KYC (biometria/prova de vida) | Contratar parceiro de KYC autorizado |
| W-02 | Geolocalização real (VPN/proxy) | Provedor de geolocalização/compliance |
| W-03 | Adapter SIGAP real (mTLS/TLS 1.2, e-CNPJ, token) | Credenciais de operador autorizado + `SIGAP_ENABLED=true` |
| W-04 | PSP/Pix real para depósitos/saques | Conta e credenciais de provedor de pagamentos |
| W-05 | Certificação SPA / auditoria externa | Operador autorizado + auditoria formal |

### Caminho de certificação

```text
BackBet → security assessment → compliance assessment → certificação aplicável
→ integração regulatória → operador autorizado → produção
```

1. **Regenere evidência**: rode `npm run security:assess` a cada release; o JSON pode ser anexado a uma auditoria.
2. **Certificação**: com operador, repetir os passos 3-6 ligando o `security:assess` como artefato de entrada.
3. **Não adiar**: certificação não se trata retroativamente com o sistema movimentando dinheiro — controles bloqueantes falhando **bloqueiam o go-live**.
