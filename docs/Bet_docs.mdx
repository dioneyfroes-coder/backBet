# Apostas, Risco e Games

Cobre `src/core/betting`, `src/core/risk` e o módulo de games (Coin Flip) com autenticação.

## Apostas (`/api/v1/bets`)

| Endpoint | Descrição |
|----------|-----------|
| `POST /api/v1/bets` | Coloca aposta (débito da carteira em transação + reserva de exposição de risco) |
| `GET /api/v1/bets` | Apostas do usuário (paginado) |
| `POST /api/v1/bets/:betId/cancel` | Cancelamento (reembolso `BET_REFUND`) |
| `GET /api/v1/events`, `/:id`, `/:id/markets`, `/:id/bets` | Eventos e mercados (públicos, exceto bets por evento) |

`placeBet` e `cancel` aceitam `Idempotency-Key`. Estados: `PENDING → WON | LOST` (resolução única), `CANCELED` (terminal).

**Fluxo de colocação**: valida usuário ativo, evento aberto, mercado aberto, odd existente e **exposição de risco** → bloqueia fundos na carteira (`WalletService.withdraw`) → persiste `Bet` `PENDING`. Invalidações: `BET_NOT_OWNER` (403), `BET_NOT_PENDING` (409), `EVENT_*`/`ODD_NOT_FOUND` (400/409), `WALLET_INSUFFICIENT_FUNDS`.

**Settlement (admin)**: `POST /api/v1/admin/bets/:id/settle` com `result: 'WIN' | 'LOST'` — credita retorno (WIN), não credita (LOST), rejeita replay (`409`) e resultado inválido (`400`). Não-admin → `403`.

## Integração de Risco (RiskService)

`src/core/risk` previne perdas excessivas e reserva exposição por usuário.

- **Pontos de integração**: `BetService.placeBet` chama `riskService.canPlaceBet(...)` **antes** do débito e `registerExposure(userId, liability)` após persistir; `cancelBet`/`resolveBet` chamam `reduceExposure(...)`.
- **Liability**: `stake * (odds - 1)` via `Money.calculateLiability()` (arredondado em centavos).
- **Regras**: velocity limit (`MAX_BETS_PER_WINDOW`/`VELOCITY_WINDOW_SECONDS`), máximos de exposição por evento/mercado (`MAX_EXPOSURE_PER_EVENT`/`MAX_EXPOSURE_PER_MARKET`), whitelist/blacklist (`WHITELIST_USER_IDS`/`BLACKLIST_USER_IDS`).
- **Persistência**: `RiskProfile` com `exposureCents`/`maxExposureCents`; fallback `InMemoryRiskRepository` quando `USE_MONGOOSE_PERSISTENCE=false`.
- **Rejeição**: resposta `400 RISK_REJECTED` **sem debitar a carteira** (testado em `RiskLimit.integration.test.ts`).
- **Observabilidade**: log estruturado `risk_reject` com `userId`, `reason`, `liability`, `currentExposure`, `maxExposure`.

## Games (Coin Flip) — `src/core/games`

| Endpoint | Auth | Descrição |
|----------|------|-----------|
| `GET /api/v1/games` | pública | Lista jogos e limites |
| `GET /api/v1/games/coin-flip` | pública | Configuração atual (min/max bet, payout) |
| `GET /api/v1/games/coin-flip/feed` | pública | Feed público (sem dados pessoais) |
| `GET /api/v1/games/coin-flip/history` | **sim** | Histórico pessoal (limit 1-50) |
| `POST /api/v1/games/coin-flip/play` | **sim** | Executa rodada `{ choice: 'HEADS'|'TAILS', wager }` |
| `POST /api/v1/games/coin-flip/play-batch` | **sim** | Várias rodadas sequenciais; retorna `rounds[]` + `totalPrize` |

- O backend debita a carteira **antes** de jogar; resposta inclui `outcome`, `result`, `payoutAmount`, `createdAt`.
- `503 GAME_DISABLED` quando `GAME_COINFLIP_ENABLED=false`; `422` para validação; `429` para throttling.
- **Prêmio fixo**: `GAME_COINFLIP_FIXED_WIN` define prêmio fixo (ignora `PAYOUT_MULTIPLIER`); `MIN_BET`/`MAX_BET` iguais fixam a aposta.
- Webhooks por rodada: `GAME_INTEGRATION_WEBHOOK_ENABLED/URL` (opcional).
- Repostas a tratar no frontend: `401` (login/refresh), `403` (jogo desligado para a conta), `422` (validação), `429` (travar botão), `503` (manutenção).

### Autenticação em games

Mesma identidade do resto da API: `Authorization: Bearer <JWT>` em produção; `ALLOW_DEV_BEARER_BYPASS=true` em dev aceita `Bearer <userId>`. Use `GET /api/v1/wallets/me` para validar saldo antes do `play`. Não exponha `userId` cru no feed (ofusque no frontend).

## Como estender o RiskService

Adicione a checagem em `RiskService.canPlaceBet` e emita log `risk_reject` quando recusar; incremente um contador de métrica (ex.: `risk_reject_total`) no mesmo local.
