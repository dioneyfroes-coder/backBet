# MongoDB e Repositórios Mongoose

Como provisionar, conectar e usar a persistência Mongo do BackBet, incluindo a integração das factories com os repositórios Mongoose.

## Por que replica set?

O BackBet usa **transações** para atomicidade entre carteira, ledger, aposta e tesouraria. O MongoDB só permite transações em **replica set** (ou sharded cluster). O compose sobe `mongodb` com `replicaSet=rs0` e a URI de exemplo carrega `replicaSet=rs0`.

```text
MONGODB_URI=mongodb://backbet:TROQUE@localhost:27017/backbet?authSource=admin&replicaSet=rs0
```

## Provisionamento (Docker Compose)

O `docker-compose.yml` define o serviço `mongodb` interno (sem porta pública) com:

- usuários `MONGO_ROOT_PASSWORD` (admin) e `MONGODB_APP_PASSWORD` (usuário da app, `readWrite`);
- banco `backbet` criado automaticamente no primeiro registro;
- replica set `rs0` inicializado no entrypoint.

Ambientes:

- **Dev in-memory**: `USE_MONGOOSE_PERSISTENCE=false` (não toca Mongo).
- **Dev real**: `USE_MONGOOSE_PERSISTENCE=true` + `MONGODB_URI` apontando para o compose.
- **Teste**: `docker-compose.test.yml` (Mongo+Redis no loopback) — usado por `test:integration:full`.
- **Produção**: Mongo privado no host (compose) ou gerenciado (Atlas) via `MONGODB_URI`.

## Repositórios Mongoose (arquitetura)

Fluxo: `Domain (interfaces) → Persistence factory → Mongoose repo → Schema → MongoDB`.

1. **Domínio** define as interfaces (`src/core/**/domain/repositories/*`).
2. **Factories** (`src/infrastructure/persistence/factory.ts`) escolhem entre in-memory e Mongo lendo `USE_MONGOOSE_PERSISTENCE` (lazy import evita carregar schemas quando a flag é false).
3. **server.ts** conecta/desconecta via `connectMongoDB()`/`disconnectMongoDB()` e registra shutdown limpo (SIGINT/SIGTERM).
4. **Casos de uso** importam apenas factories — alternar memória/Mongo não exige mudança de código.

### Matriz de repositórios

| Contexto | Interface | Implementação Mongo | Schema | Observações |
| --- | --- | --- | --- | --- |
| Usuários | `IUserRepository` | `MongooseUserRepository.ts` | `UserSchema.ts` | Índices únicos em `email`/`username`; sincroniza `providerId` |
| Carteiras | `IWalletRepository` | `MongooseWalletRepository.ts` | `WalletSchema.ts` | `balanceCents`/`lockedBalanceCents`; versão otimista (`version`) |
| Apostas | `IBetRepository` | `MongooseBetRepository.ts` | `BetSchema.ts` | Índices por `status`/`userId`/`eventId`; settlement idempotente |
| Eventos | `IEventRepository` | *(in-memory)* | — | Planejado coleção futura |
| Pacotes de crédito | `ICreditPackageRepository` | `MongooseCreditPackageRepository.ts` | `CreditPackageSchema.ts` | `bonusPercent` derivado no domínio |
| Solicitações de saque | `IWithdrawalRequestRepository` | `MongooseWithdrawalRequestRepository.ts` | `WithdrawalRequestSchema.ts` | Audit trail (`approverId`, `approvedAt`) |
| Risco | `IRiskRepository` | `MongooseRiskRepository.ts` | `RiskProfileSchema.ts` | `exposureCents`/`maxExposureCents`; `InMemoryRiskRepository` fallback |
| Ledger | `ILedgerRepository` (finance) | Mongoose | `LedgerEntrySchema.ts` | Append-only, `transactionId` único (índice) |
| Auditoria | `IAuditEventRepository` | `MongooseAuditEventRepository.ts` | `AuditEventSchema.ts` | Eventos imutáveis + retenção |
| Idempotência | `MongoIdempotencyStore` | Mongo | idempotency | Alternativa ao Redis |

### Padrões de implementação

- **Mapeamento**: helpers `toDomain`/`toPersistence`; nunca manipular documentos na aplicação.
- **Lean queries**: `.lean({ virtuals: true })` para leituras.
- **Upsert idempotente**: `findOneAndUpdate({ _id }, dto, { upsert: true })`.
- **Erros padronizados**: violação de índice/inesperado → `AppError` (`CONFLICT`, `INTERNAL_SERVER_ERROR`); trate com `AppError.isAppError`.
- **Locking otimista**: carteira usa `version` no filtro da atualização; conflito → `409`.

### Índices e migrações

- Índices definidos via `schema.index(...)` em `src/infrastructure/persistence/mongoose/schemas/**/*`; o Mongoose sincroniza no boot, mas valide com `db.<collection>.getIndexes()` em produção.
- Mudanças estruturais grandes → scripts em `scripts/migrations/<timestamp>.ts` ou runbook.

## Troubleshooting

| Sintoma | Causa/solução |
|---------|---------------|
| `Transaction numbers are only allowed...` | Mongo não está em **replica set** — suba com `replicaSet=rs0` |
| `MongoDB connection failed` no boot | URI/credenciais erradas; `mongosh` para testar; container ativo? |
| `duplicate key error` | Índice único violado → tratar `CONFLICT`; conferir `findByEmail`/`findByUserId` antes |
| `/readiness` → `mongo: down` | Flag habilitada sem banco disponível; ver `readiness_dependency` nos logs |
| `Topology was destroyed` | Conexão encerrada abruptamente; garantir `retryWrites=true` e keep-alive |

## Checklist para novos repositórios

- [ ] Interface em `core/<context>/domain/repositories`.
- [ ] Schema em `infrastructure/persistence/mongoose/schemas` com índices explícitos.
- [ ] Implementação adicionada à factory em `persistence/factory.ts`.
- [ ] Testes de conversão domínio ↔ persistence.
- [ ] Documentado aqui se novos env vars forem necessários.
