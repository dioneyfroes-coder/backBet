# Guia Rápido

Guia de como subir o BackBet localmente, escolher o modo de persistência e rodar as rotinas de qualidade.

## Pré-requisitos

- **Node.js ≥ 22** (recomendado via `nvm`).
- **Docker + Docker Compose** para infraestrutura real (Mongo replica set `rs0` + Redis) e testes de integração.
- **npm** incluído no Node.

## Setup em 5 passos (sem infra — in-memory)

1. Instale dependências: `npm install`
2. Copie o exemplo: `cp .env.example .env`
3. Edite o `.env`: `NODE_ENV=development`, `BACKBET_RUNTIME_ENV=development` e um `JWT_SECRET` forte (`openssl rand -hex 32`).
4. Desative infra para rodar em memória: `USE_MONGOOSE_PERSISTENCE=false` e `CACHE_ENABLED=false`.
5. Suba em dev com hot reload: `npm run dev` → teste `http://localhost:3000/health`.

> `JWT_SECRET` é obrigatório — o boot lança erro sem ele. `MONGODB_URI`/`REDIS_URL` são obrigatórios em produção apenas.

## Com infraestrutura real (Mongo + Redis)

Recomendado para testar transações, idempotência e workers:

```bash
docker compose up -d mongodb redis      # sobe Mongo (replica set rs0) + Redis
```

No `.env`, aponte a aplicação:

```text
USE_MONGOOSE_PERSISTENCE=true
MONGODB_URI=mongodb://backbet:TROQUE@localhost:27017/backbet?authSource=admin&replicaSet=rs0
REDIS_URL=redis://localhost:6379
CACHE_ENABLED=true
```

Depois `npm run dev` e valide `/health`, `/readiness` e `/health/cache`.

> A configuração completa de banco (credenciais, secção de usuários, replica set) está em `docs/MONGODB_SETUP.mdx`.

## Tudo em Docker

```bash
docker compose up -d --build
```

Sobe o host único: Mongo (rs0) + Redis + API + workers. A API fica em `http://localhost:3000`.

- `docker-compose.test.yml` — infra de teste isolada (loopback).
- `docker-compose.proxy.yml` — Caddy/TLS opcional.
- `docker-compose.observability.yml` — Prometheus/Grafana/OTEL opcional (habilita `/metrics` com `OBS_ENABLE_PROMETHEUS=true`).

## Variáveis de ambiente mais comuns

| Variável | Padrão | Descrição |
|---|---|---|
| `NODE_ENV` | — | `development` / `test` / `production` |
| `BACKBET_RUNTIME_ENV` | — | Ambiente de runtime do BackBet (`development` local deve estar explícito para o bypass de auth) |
| `JWT_SECRET` | — | **Obrigatória sempre**; assina tokens |
| `MONGODB_URI` / `REDIS_URL` | — | Obrigatórias em produção; usadas com `USE_MONGOOSE_PERSISTENCE=true` |
| `USE_MONGOOSE_PERSISTENCE` | `false` | `true` para Mongo real; `false` usa repositórios in-memory |
| `CACHE_ENABLED` | — | Liga/desliga cache Redis |
| `ALLOW_DEV_BEARER_BYPASS` | — | `true` só em dev: aceita `Bearer <userId>` sem JWT válido |
| `PIX_PROVIDER` | `mock` | Provedor PIX (mock hoje; provedor real é pendência W-04) |
| `PIX_WEBHOOK_ENABLED` | `false` | Habilita `POST /api/v1/webhooks/pix` |
| `TRACING_ENABLED` | `false` | OpenTelemetry (OTLP) |
| `OBS_ENABLE_PROMETHEUS` | `false` | Ativa `/metrics` (Prometheus) |
| `OBS_ENABLE_EMAIL_ALERTS` | `false` | Alertas por e-mail (requer SMTP) |
| `AUDIT_RETENTION_DAYS` | `1825` | Retenção de auditoria (5 anos) |
| `SIGAP_ENABLED` | `false` | Liga o job de transmissão SIGAP |
| `SIGAP_RETRY_MAX_ATTEMPTS` | `5` | Máximo de tentativas de transmissão SIGAP |
| `RATE_LIMIT_*`, `AUTH_*_RATE_LIMIT_*`, `WALLET_*_RATE_LIMIT_*`, `BET_*_RATE_LIMIT_*` | — | Taxas de rate limit global e por rota |

## Troubleshooting

| Sintoma | Causa provável / solução |
|---|---|
| Boot falha com "JWT_SECRET" ausente | Defina `JWT_SECRET` no `.env` (obrigatória sempre) |
| `MONGODB_URI` não conecta | Confira se o Mongo é **replica set** (transações exigem `replicaSet=rs0`); veja `docs/MONGODB_SETUP.mdx` |
| `409` em depósito/aposta | Lock otimista ou idempotência: repita apenas a mesma chave com os mesmos dados |
| `/metrics` responde `410` | Normal: ative `OBS_ENABLE_PROMETHEUS=true` apenas se precisar |
| Porta 3000 ocupada | Mude `PORT` no `.env` ou libere a porta |
| Testes de integração falham | Suba a infra de teste: `npm run test:infra:reset` |
| Sem `accessToken` no registro | Usuário ficou `PENDING_VERIFICATION`; faça polling em `GET /api/v1/auth/register/status/:userId` |
