# BackBet Quickstart

Checklist para sair do zero até um ambiente funcional com saúde/observabilidade verificadas e testes em dia.

## 1. Pré-requisitos

- Node.js **20.x** (18 funciona, mas todas as automações rodam em 20) e npm **10+**
- Git + `tsc` (instalado via `npm install`)
- Docker 24+ (opcional, mas recomendado para MongoDB/Redis)
- Porta `3000` livre (override via `PORT`)

## 2. Clone e dependências

```bash
git clone https://github.com/<sua-org>/backbet.git
cd backbet
npm install
```

> Sempre use `npm install` (o projeto usa lockfile npm). `npm ci` é recomendado em CI/CD.

## 3. Variáveis de ambiente

```bash
cp .env.example .env
```


## 7. Monitoramento diário

- `npm run pm2:webui:start` para abrir o painel na porta `PM2_WEB_PORT` (default `9615`).
- Acesse via túnel/proxy seguro e acompanhe CPU, memória e restarts do processo `backbet`.
- Para complementar, rode `npm run pm2:webui:logs` e mantenha Uptime Robots/Synthetics consultando `/health`/`/readiness`.
- Suba o processo de alertas com `npm run pm2:health:start` (usa `HEALTH_MONITOR_*` + `SMTP_*`) ou execute pontualmente com `HEALTH_MONITOR_RUN_ONCE=true npm run health-monitor:start`.
- Finalize com `npm run pm2:webui:stop` e `npm run pm2:health:stop`, ou use `pm2 monit` quando o painel não estiver disponível.
Ajuste os principais toggles:

| Variável | O que faz | Valor típico em dev |
|----------|-----------|---------------------|
| `NODE_ENV` | Ambiente lógico | `development` |
| `PORT` | Porta HTTP | `3000` |
| `USE_MONGOOSE_PERSISTENCE` | Liga repositórios Mongo/Mongoose | `false` se quiser in-memory |
| `MONGODB_URI` / `MONGODB_DB_NAME` | Conexão Mongo | `mongodb://localhost:27017` / `backbet-dev` |
| `CACHE_ENABLED` / `REDIS_URL` | Libera cache Redis + métricas | `false` quando não houver Redis |
| `ALLOW_DEV_BEARER_BYPASS` | Permite `Authorization: Bearer <userId>` sem JWT | `true` | 
| `IDENTITY_PROVIDER_*` | Credenciais do provedor de identidade | Use valores reais só em staging/prod |
| `JWT_*` | Segredo/local auth | Necessário para `/auth/login` e `/auth/refresh` |
| `RATE_LIMIT_*` | Rate limit global | Defaults altos (5k req/10 min) |
| `TRACING_ENABLED`, `OTEL_EXPORTER_OTLP_ENDPOINT` | OpenTelemetry | Ative apenas se tiver collector |

> Nunca versione `.env`. Para CI, configure secrets no provedor.

## 4. Dependências locais (Mongo + Redis)

Subindo apenas para desenvolvimento neste PC (Mongo e Redis juntos):

```bash
docker run -d --name backbet-mongo -p 27017:27017 mongo:7
docker run -d --name backbet-redis -p 6379:6379 redis:7
```

> Se o banco/ambiente for o de teste com Docker em servidores locais, use os
> compose da **Fase 17** (ver `docs/DOCKER.mdx`):
>
> - `docker-compose.mongo.yml` — MongoDB no **server02** (replica set `rs0`);
> - `docker-compose.yml` — aplicação + Redis + workers no **server01**,
>   consumindo o Mongo do server02 via `MONGODB_URI`.

> Sem Mongo? defina `USE_MONGOOSE_PERSISTENCE=false`. Sem Redis? `CACHE_ENABLED=false`.

## 5. Executar em desenvolvimento

```bash
npm run dev
```

- Usa `tsx watch src/index.ts` com reload automático.
- O bootstrap (`src/index.ts`) inicia tracing antes de carregar o `ApiServer`.
- Logs são JSON com `request_start`/`request_end`/`request_error` e sempre incluem `requestId`.

### Endpoints importantes

| URL | Descrição |
|-----|-----------|
| `GET /health` | Heartbeat e uptime |
| `GET /readiness` | Consulta Redis/Mongo e atualiza `dependencyHealthSnapshot` |
| `GET /health/cache` | Exibe métricas internas do `RedisClient` |
| `GET /metrics` | Desativado (410) por padrão — habilite `OBS_ENABLE_PROMETHEUS=true` se precisar do Prometheus legado |
| `GET /api/docs` | Swagger UI |
| `GET /api/docs.json` | OpenAPI 3.1 |

### Contact worker (fila de emails)

O sistema enfileira mensagens de contato em `contact_queue` e requer um worker para processá-las em produção.

- Em desenvolvimento você pode rodar o worker TypeScript diretamente com `tsx`:

```bash
npm run worker:contact
```

- Com PM2 (desenvolvimento, sem build):

```bash
pm2 start ecosystem.contact.dev.config.cjs --env development
```

- Em produção (após `npm run build`):

```bash
npm run build
pm2 start ecosystem.contact.config.cjs --env production
```

Variáveis relevantes:

- `USE_REDIS_QUEUE=true` — ativar Bull+Redis em produção.
- `REDIS_URL` — conexão Redis para a fila.
- `MAILER_SMTP_URL` — URL SMTP (opcional; se ausente o worker usa `jsonTransport` para não enviar emails reais em dev).
- `CONTACT_TO_EMAIL` — destino padrão das mensagens de suporte.


## 6. Scripts essenciais

| Comando | Uso |
|---------|-----|
| `npm run dev` | Desenvolvimento com hot reload |
| `npm run build` | `tsc` + `tsc-alias` para `dist/` |
| `npm start` | Executa `dist/index.js` (produção/staging) |
| `npm test` | 350 testes (unit + integração leve) |
| `npm run test -- --coverage` | Relatório completo de cobertura |
| `npm run lint` / `npm run lint:fix` | ESLint 9 + `@typescript-eslint` |
| `npm run format` | Prettier |
| `npm run migration:run` | Runner de migrations (Mongo) |
| `npm run seed:initial` / `npm run seed:credit-packages` | Seeds utilitários |

Para executar a suíte de integração real com MongoDB e Redis, isole um banco de teste e rode:

```bash
RUN_REAL_INTEGRATION_TESTS=true \
MONGODB_URI=mongodb://localhost:27017/backbet-integration \
MONGODB_DB_NAME=backbet-integration \
REDIS_URL=redis://localhost:6379 \
npm test -- --runInBand src/integration/__tests__/mongo-redis.integration.test.ts
```

Essa suíte é ignorada quando `RUN_REAL_INTEGRATION_TESTS` não é `true`; nunca aponte para dados de produção.

## 8. Testes, qualidade e build

1. `npm run lint`
2. `npm run test -- --coverage`
3. `npm run build`

> Essa trinca é obrigatória antes de qualquer PR. `npm run build && npm start` garante que o bundle em `dist/` funciona.

## 9. Troubleshooting

| Sintoma | Correção |
|---------|----------|
| `Cannot find module` ao rodar `npm start` | Remova `dist/` e refaça `npm run build`. Confirme `npm install` e tsconfig correto. |
| `ERR_UNKNOWN_FILE_EXTENSION` | Garanta que `package.json` **não** tenha `"type": "module"`. |
| `MongoNetworkError` | Suba Mongo (`docker ps`), revise URI ou use `USE_MONGOOSE_PERSISTENCE=false`. |
| `Redis connection refused` | Corrija `REDIS_URL` ou desligue cache (`CACHE_ENABLED=false`). |
| `IDENTITY_PROVIDER_*` faltando | Use chaves reais do provedor de identidade ou habilite `ALLOW_DEV_BEARER_BYPASS` (apenas em dev/test). |
| Testes instáveis | `npm test -- --clearCache && npm test`. Confira se serviços externos não estão caindo. |
| Porta 3000 ocupada | Ajuste `PORT` ou finalize processo (`lsof -i :3000`). |

## 10. Próximos passos

1. Rodar `npm run lint && npm run test -- --coverage && npm run build` antes de commitar.
2. Atualizar documentação do módulo tocado em `docs/*.mdx` quando necessário.
3. Em staging/prod: ative Redis real, conecte Mongo definitivo, defina variáveis do provedor de identidade (ex.: `IDENTITY_PROVIDER_*`), configure OTLP (`TRACING_ENABLED=true` + `OTEL_EXPORTER_OTLP_ENDPOINT`) e proteja `/health/cache` + `/readiness` via proxy (`/metrics` responde 410 até que `OBS_ENABLE_PROMETHEUS=true`).
