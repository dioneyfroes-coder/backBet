# Certificação e Preparação para Operação Real (Fase 35)

Documento formal da Fase 35 — **Certificação e preparação para operação real**.
Complementa `docs/SECURITY-OPS.mdx` (checklist pré-deploy, Fase 27) e
`docs/SIGAP_CONFORMIDADE.mdx` (Fase 16) com a **matriz de controles que a SPA
exige** ((UNINCORPORATED) — Secretaria de Prêmios e Apostas do Ministério da
Fazenda) mapeados para **evidências objetivas no repositório**.

O que pode ser feito **em desenvolvimento** sem operador autorizado, provedores
externos ou certificação formal está aqui e é **verificável por máquina** via:

```bash
npm run security:assess
```

O script varre o repositório, confere cada controle contra a evidência (arquivo,
configuração ou código) e escreve o relatório em
`reports/security-assessment-<timestamp>.txt` (e `.json`). Sai com código 1 se
algum controle **bloqueante** falhar — mesmo espírito do `npm run check:secrets`.

## Observações e próximos passos

1. **Regenerar evidência**: a matriz acima é executável — rode
   `npm run security:assess` a cada release. O relatório JSON pode ser anexado a
   um processo de auditoria.
2. **Certificação**: quando houver operador autorizado, repetir os passos 3 a 6
   do plano (certificação aplicável, integração regulatória, operador
   autorizado, produção) ligando o `security:assess` como artefato de entrada.
3. **Não adiar para "depois"**: conforme o plano, certificação não é tratada
   retroativamente com o sistema já movimentando dinheiro; os controles
   bloqueantes acima são **gatilhos** — qualquer um falhando bloqueia o go-live.
