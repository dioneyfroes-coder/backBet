# Arquitetura BackBet

O BackBet é um monólito modular escrito em TypeScript/Node 22+ que aplica princípios de **DDD**, **ports & adapters** e **observabilidade nativa**. Todo o código vive em `src/` e é separado em camadas coerentes:

1. **Interface / API (`src/infrastructure/api`)** – Express 5, controllers, DTOs e middlewares.
2. **Aplicação (`src/core/**/application`)** – use cases e serviços orquestradores que conversam por interfaces.
3. **Domínio (`src/core/**/domain`)** – entidades, value objects e regras puras.
4. **Infraestrutura (`src/infrastructure/*`)** – persistência, cache, autenticação, observabilidade e config.
5. **Shared (`src/shared`)** – erros, configs, request context e utilidades reutilizadas.

## Bounded Contexts

| Contexto | Diretório | Responsabilidades chave | Principais agregados |
|----------|-----------|-------------------------|----------------------|
| User Core | `src/core/user` | Cadastro, autenticação local, perfil, preferências, upload de documentos | `User`, `Email` VO |
| Finance Core | `src/core/finance` | Carteiras, depósitos/saques, pacotes de crédito, workflow de saques | `Wallet`, `Money`, `Currency` |
| Betting Core | `src/core/betting` | Eventos, odds, colocação/cancelamento/resolução de apostas | `Bet`, `Event`, `Odds` |
| Risk Core | `src/core/risk` | Exposição por usuário, contadores de reserva atômica, limites | `RiskProfile`, `RiskExposureCounter` |
| Treasury | `src/core/treasury` | `HouseTreasuryService`, reconciliação, relatórios financeiros | `HouseWallet`, entradas de legado |
| Compliance | `src/core/compliance` | Gates de saque via ports de KYC/geolocalização/device | — |
| Responsible Gambling | `src/core/responsibleGambling` | Limites de depósito/aposta e auto-exclusão | `ResponsibleGamblingProfile` |
| Audit | `src/core/audit` | Eventos append-only + retenção | `AuditEvent` |
| SIGAP | `src/core/sigap` | Transmissão regulatória com ciclo ACK/REJECT + retry | `SigapTransmission` |
| Games | `src/core/games` | Mini games (Coin Flip) | `GameRound` |
| Shared Kernel | `src/core/shared` | `AggregateRoot`, `UniqueId`, `Result`, `DomainError`, DTOs paginados | — |

Cada contexto expõe interfaces (`IUserRepository`, `IWalletRepository`, `IBetRepository`, etc.) consumidas pela camada de aplicação. Implementações concretas são providas por factories (in-memory / Mongoose).

## Camadas em Detalhe

### 1. API Layer (`src/infrastructure/api`)
- **`ApiServer.ts`** monta Express 5 com `helmet`, CORS por allowlist, `express-rate-limit` (global + por rota), parsers (`express.json({ limit: '10mb' })`), Swagger UI (`/api/docs`) e endpoints de saúde.
- Middlewares próprios: `requestIdMiddleware`, `loggingMiddleware` (logs JSON request_start/end/error) e handlers de erro padronizados (`BaseController`).
- Autenticação: Passport (`passport-jwt`) em produção; bypass explícito em dev (`ALLOW_DEV_BEARER_BYPASS`).
- Rotas residem em `routes/*.ts` e importam controllers do respectivo módulo; registradas via `createApiRouter` sob `/api/v1`.

### 2. Application Layer
- Use cases em `src/core/<context>/application/use-cases` (ex.: `RegisterUser`, `DepositFunds`, `PlaceBet`, `RequestWithdrawal`, `ReconcileTreasury`).
- Cada caso injeta repositórios + serviços via construtor (DI manual) e retorna `Result<T>`.
- Hooks de cache são chamados aqui para manter o domínio puro.

### 3. Domain Layer
- Entidades estendem `AggregateRoot` e expõem métodos para mutações válidas (`Wallet.lockFunds`, `Bet.cancel`).
- Value Objects encapsulam validações (`Email`, `Money`, `Odds`, `BetAmount`).
- Erros de domínio herdam de `DomainError`, traduzidos para `AppError` na camada API.

### 4. Infraestrutura
- **Persistência (`src/infrastructure/persistence`)**: `factory.ts` escolhe Mongoose (`persistence/mongoose/*`) ou adaptadores in-memory; conexão Mongo garante replica set para transações.
- **Cache (`src/infrastructure/cache`)**: `RedisClient` (ioredis), hooks declarativos e TTLs em `shared/config/cacheConfig.ts`.
- **Auth (`src/infrastructure/auth`)**: `JwtService` + estratégias Passport.
- **Observabilidade (`src/infrastructure/observability`)**: snapshots (cache/resiliência/dependências) e tracing OpenTelemetry (`tracing.ts`).
- **Jobs**: `SigapTransmissionJob`, `AuditRetentionJob`, workers Bull de contato/saque.
- **Config (`src/shared/config/*.ts`)**: fonte única para envs, rate limit, CORS, security, cache, audit, SIGAP e OTLP.

### 5. Shared Layer (`src/shared`)
- `errors/AppError`, `observability/requestContext` (AsyncLocalStorage), helpers de logging e tipos comuns; loaders `env.ts`/`appConfig.ts`/`cacheConfig.ts`/`observabilityConfig.ts`.

## Fluxo de Requisição

1. **Entrada HTTP** – `ApiServer` aplica helmet, CORS, rate-limit, request-id e logging.
2. **Autenticação** – Passport/JWT preenche `req.auth.userId`; rotas críticas usam `protectedRoute`; rotas admin usam `requireAdminRole`.
3. **Controller/DTO** – `BaseController` + Zod validam input e produzem resposta uniforme.
4. **Use Case** – Execução orquestrando domínios, repositórios e cache.
5. **Repositórios** – Factories resolvem `create<User|Wallet|Bet>Repository()`.
6. **Cache/Side effects** – Hooks Redis atualizam perfis, saldos, odds; eventos de auditoria/tracing emitidos.
7. **Resposta** – Envelope JSON com `success`, `data/error` e `meta` (timestamp + `requestId`).

## Persistência e Transações

- Mongo roda como **replica set** (`rs0`); transações cobrem **wallet/ledger/bet/treasury** de forma atômica (ACID).
- **Concorrência**: locking otimista (`HouseWallet.version` → `409 CONFLICT` em escrita obsoleta) + `IdempotencyService` (`SET NX` no Redis; replay devolve o mesmo resultado; payload diferente → `409`) + retry transitório com backoff exponencial/jitter (`retryTransient.ts`) em `WalletService.run()` e `BetService.placeBet()`.
- Factories leem `USE_MONGOOSE_PERSISTENCE`; em produção `server.ts` garante `connectMongoDB()` antes de montar o server e registra shutdown limpo.

## Cache, Rate Limiting e Confiabilidade

- **Cache Redis** (`CACHE_ENABLED`): hooks `cacheUserProfile`, `cacheWalletBalance`, `cacheWalletHistory`, `cacheEventOdds` + flush após mutações.
- **Rate limiting**: global (`RATE_LIMIT_*`) e por rota (`AUTH_*`, `WALLET_*`, `BET_*`).
- **Request context**: `AsyncLocalStorage` propaga `requestId/userId` para logs e erros.
- **Health/Readiness**: `/health`, `/readiness`, `/health/cache` e snapshots de dependência alimentam PM2 WebUI e alertas.

## Observabilidade

- **Logs JSON**: middleware escreve `request_start`, `request_end` e `request_error` com `requestId`, método, rota e duração — nunca segredos.
- **Snapshots**: `cacheMetricsSnapshot`, `resilienceMetricsSnapshot` e `dependencyHealthSnapshot` expostos via `/health/cache` e `/readiness`.
- **Tracing**: OpenTelemetry (Express/Mongoose/ioredis) quando `TRACING_ENABLED=true`, exportado via OTLP.
- **Métricas**: `/metrics` responde `410 Gone` por padrão; só é ativo com `OBS_ENABLE_PROMETHEUS=true` (uso opcional em dev). Em produção, alertas por regras em `deploy/observability/alerting/alerts.yml` (12 regras) + e-mail.
- **Drill centrais**: `npm run backup:*`, `npm run security:assess`, `npm run health-monitor:start`.

## Fluxos Críticos

### Registro de Usuário + Carteira
`POST /api/v1/auth/register` → AuthController valida (Zod) → `RegisterUser` cria `User` e `Wallet` (BRL) → resposta inclui `accessToken`/`refreshToken` quando ativo; usuário `PENDING_VERIFICATION` faz polling em `GET /api/v1/auth/register/status/:userId` até `isActive=true`.

### Depósito / Saque
`POST /api/v1/wallets/deposit | withdraw` → rate limit + auth → reserva `Idempotency-Key` → `WalletService.deposit/withdraw` (Money/Currency) em transação + ledger → cache atualizado. Webhook `POST /api/v1/webhooks/pix` (HMAC `X-BackBet-Signature`) credita/estorna via `PIX_PAID`/`PIX_REFUNDED`.

### Colocar/Cancelar Aposta
`POST /api/v1/bets` → `BetService` valida usuário ativo, mercado aberto, odds e exposição (`risk`) → bloqueia fundos na carteira em transação → persiste `Bet` `PENDING` → cancelamento reverte via `WalletService.deposit` em transação.

### Transmissão SIGAP
`SigapTransmissionJob` envia apostas/eventos ao adapter (mock em dev); o resultado é `SigapTransmissionResult = ACKED | REJECTED`. REJECTED dispara **retry** (padrão `SIGAP_RETRY_MAX_ATTEMPTS=5`, backoff) e incrementa a métrica `backbet_sigap_submission_rejected_total`. Auditoria registra cada tentativa. Detalhes: `docs/SIGAP_CONFORMIDADE.mdx`.

### Auditoria
`AuditService.recordAdminAction` persiste `AuditEvent` (append-only); `AuditRetentionJob` remove eventos mais antigos que `AUDIT_RETENTION_DAYS` (1825 = 5 anos), registrando um evento `DATA_RETENTION` a cada execução. `AdminController` registra `bet.settle`, `event.status`, `risk.user.reconcile`.

## Segurança

- Autenticação JWT (Passport) + `requireAdminRole` para backoffice; bcrypt custo 12.
- Helmet, CORS allowlist, rate limiting, payload limit e validação Zod em todas as entradas.
- `npm run check:secrets` falha o build se encontrar segredo rastreado pelo Git; boot de `env.ts` lança sem `JWT_SECRET` e nunca loga valores.
- Endurecimento pré-deploy em `deploy/harden-server.sh` (UFW, SSH por chave, unattended-upgrades) — detalhes em `docs/DEPLOY.mdx`.

## Roadmap Arquitetural

1. **Eventos de domínio/Outbox** – formalizar `BetPlaced`, `FundsWithdrawn` etc. para integrações futuras.
2. **Persistência única (Mongo)** – remover fallback in-memory em produção e habilitar migrações automáticas.
3. **Feature Flags** – mover toggles críticos (bypass auth, cache) para um provider dedicado.
4. **Escala Horizontal** – múltiplas instâncias atrás de um ingress; filas Bull requeren Redis compartilhado (já é o caso).
5. **Provedores reais** – adapter SIGAP mTLS, KYC/geolocalização/PSP (W-01..W-05, ver `docs/SIGAP_CONFORMIDADE.mdx`).
