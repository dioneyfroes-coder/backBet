# Persistência e Repositórios

Este documento descreve a estratégia de persistência usada no projeto, como a fábrica (`factory.ts`) expõe repositórios e como alternar entre implementações em memória e Mongoose.

## Fábrica de persistência

O arquivo `src/infrastructure/persistence/factory.ts` centraliza a criação de repositórios. Para cada contrato (ex.: `IBetRepository`, `IUserRepository`, `IRiskRepository`) a fábrica retorna a implementação apropriada conforme variáveis de ambiente.

## Toggle Mongoose vs In-memory

- Variável de ambiente `USE_MONGOOSE_PERSISTENCE` (string `'true'`): quando presente, a fábrica retorna as implementações Mongoose.
- Caso contrário, a fábrica usa implementações em memória como fallback — útil em CI/local sem MongoDB.

Exemplo de uso em produção:

```
export function createRiskRepository() {
  if (process.env.USE_MONGOOSE_PERSISTENCE === 'true') {
    return new MongooseRiskRepository(RiskProfileModel);
  }
  return new InMemoryRiskRepository();
}
```

## Mongoose: pontos de atenção

- Ao escrever testes para repositórios Mongoose, muitas chamadas são encadeadas (`Model.findOne().lean()`): ao mockar, retorne um objeto que implemente `.lean()` que resolve a doc.
- Algumas correções históricas: erros lançados por `MongooseRiskRepository` foram ajustados originalmente para respeitar a assinatura `AppError(code, message, statusCode, details)`.

## InMemory (desenvolvimento)

- `src/infrastructure/persistence/inmemory/repositories/InMemoryRiskRepository.ts` mantém um `Map` por `userId` com a exposição atual e fornece operações atômicas simuladas.
- Útil para executar testes locais sem dependência de infra externa.

## Recomendações

- Use o fallback in-memory para testes rápidos e CI.
- Habilite Mongoose em ambientes de staging/prod apenas quando o Mongo estiver disponível e com a string de conexão correta.
