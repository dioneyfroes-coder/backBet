# BackBet

Backend de apostas esportivas em **TypeScript + Node 22+** (Express 5), organizado em camadas limpas e DDD. Toda a API pública vive sob o prefixo versionado **`/api/v1`**, o dinheiro é tratado em **centavos inteiros** (sem floats) e a concorrência é protegida por **idempotência** (`Idempotency-Key`), **locking otimista** e **transações Mongo** (replica set).

## O que é e qual problema resolve

BackBet resolve o problema central de um backoffice de apostas: garantir que **fluxos de dinheiro sejam exatos e concorrentes** — depósitos, saques, apostas e tesouraria sem erro de arredondamento e sem saldo "perdido" por corrida de requisições. Para isso, combina:

- **DDD + camadas limpas**: domínio isolado em `src/core/*`, use cases no padrão `Result`, repositórios trocáveis (in-memory / Mongoose).
- **Dinheiro em centavos**: aritmética inteira (`Money`, `BetAmount`), API sempre em reais.
- **Concorrência defensiva**: `Idempotency-Key` em escritas críticas + `HouseWallet` com `version` e `409 CONFLICT` + retry transitório com backoff exponencial.
- **Persistência transacional**: MongoDB como replica set (`rs0`) habilita transações atômicas entre carteira, ledger, aposta e tesouraria.
- **Operação simples**: health/readiness, logs JSON, PM2 + workers Bull, Docker Compose replicável, backup/restore testado.

## Arquitetura

Monólito modular com dependência sempre apontando para dentro:

```
API (Express 5) ▸ Application (use cases) ▸ Domain (entidades/VOs) ▸ Infrastructure ▸ Shared
```

| Contexto | Diretório | Responsabilidades |
|----------|-----------|-------------------|
| User Core | `src/core/user` | Registro, login/JWT, perfil, preferências, recuperação de senha, upload de documentos |
| Finance Core | `src/core/finance` | Carteiras, depósitos, saques, pacotes de crédito, tesouraria (`HouseWallet`) |
| Betting Core | `src/core/betting` | Eventos, odds, colocar/cancelar/resolver apostas |
| Risk Core | `src/core/risk` | Perfil de exposição, contadores de reserva e limites por usuário |
| Treasury | `src/core/treasury` | `HouseTreasuryService`, reconciliação diária e relatórios financeiros |
| Compliance | `src/core/compliance` | Ports plugáveis de KYC, geolocalização e integridade de dispositivo |
| Responsible Gambling | `src/core/responsibleGambling` | Limites e auto-exclusão configuráveis por usuário |
| Audit | `src/core/audit` | Eventos de auditoria append-only + retenção (5 anos) |
| SIGAP | `src/core/sigap` | Transmissão regulatória de apostas com ciclo ACK/REJECT + retry |
| Games | `src/core/games` | Mini games (Coin Flip: jogar em lote, feed, histórico) |
| Shared Kernel | `src/core/shared` | `AggregateRoot`, `UniqueId`, `Result`, `AppError`, DTOs |

Interfaces (`IUserRepository`, `IWalletRepository`, `IBetRepository`, ...) isolam o domínio; a fábrica em `src/infrastructure/persistence/factory.ts` escolhe o adaptador (in-memory ou Mongo/Mongoose).

## Stack

| Camada | Tecnologia |
|--------|-----------|
| Runtime | Node >= 22, TypeScript 5.9 (`tsx` em dev, `tsc` + `tsc-alias` no build) |
| API | Express 5, Zod (validação de DTOs), helmet, cors, express-rate-limit |
| Auth | Passport + `passport-jwt`, `JwtService` local; bypass em dev (`ALLOW_DEV_BEARER_BYPASS`) |
| Dados | MongoDB/Mongoose (replica set `rs0`), Redis (`ioredis`, cache + filas Bull) |
| Workers | Bull (contato, saque, SIGAP, auditoria) — adaptador em memória em dev/test |
| Observabilidade | `/health`, `/readiness`, request-id + logs JSON, OpenTelemetry (OTLP), PM2 WebUI + health-monitor, alertas (12 regras) |

## Como executar

1. `cp .env.example .env`
2. Ajuste o essencial: `NODE_ENV=development`, `BACKBET_RUNTIME_ENV=development`, `JWT_SECRET`.
3. Sem infra: `USE_MONGOOSE_PERSISTENCE=false` e `CACHE_ENABLED=false` (in-memory). Para Mongo/Redis reais, defina `MONGODB_URI` e `REDIS_URL`.
4. `npm install`
5. `npm run dev` (hot reload) e teste em `http://localhost:3000/health`.

Ambientes, env vars e troubleshooting: `docs/QUICKSTART.mdx` e `docs/MONGODB_SETUP.mdx`.

## Como usar a API

- **Base URL**: `http://localhost:3000` (dev) / `https://api.backbet.com` (prod). **Todas** as rotas públicas usam `/api/v1`.
- **Envelope**: `{ success, data|error, meta: { requestId, timestamp } }`.
- **Auth**: `Authorization: Bearer <JWT>`; `GET /api/v1/events/*`, `/api/v1/games/*`, `/api/v1/auth/*` e `POST /api/v1/contact` são públicas.
- **Idempotência**: `POST /api/v1/wallets/deposit`, `/api/v1/wallets/withdraw`, `/api/v1/bets`, `/api/v1/bets/:betId/cancel` aceitam `Idempotency-Key` e respondem `Idempotency-Replayed: true` em replay.
- **Paginação**: `?limit=` (max 200, default 50) e `?offset=` (default 0) em listagens.
- **Swagger**: `GET /api/docs` (UI) e `GET /api/docs.json` (spec). Artefato gerado: `docs/openapi.json`.

Contrato completo (códigos de erro, exemplos e fluxos): `docs/API_CONTRACT.mdx`.

## Como o dinheiro funciona

- **Centavos**: todo valor interno é inteiro em centavos (`Money`, `BetAmount`); a API expõe reais. Nada de `float` em fluxo de valor.
- **Carteira**: saldo por usuário (`Wallet`) movimentado via transações financeiras; cache Redis invalidado após mutações.
- **Tesouraria**: `HouseWallet` concentra ganhos/perdas do operador e é o alvo dos settlements.
- **Saques/depósitos**: PIX via `PIX_PROVIDER=mock` com fila `Bull` para saques (e webhook `PIX_PAID`/`PIX_REFUNDED` quando habilitado).
- **Rate limits**: globais + específicos (`AUTH_*_RATE_LIMIT_*`, `WALLET_*_RATE_LIMIT_*`, `BET_*_RATE_LIMIT_*`).
- **Invariantes**: FI-01..FI-10 testados (`docs/Finance_docs.mdx`).

## Como a concorrência funciona

- **Idempotência**: escritas críticas reservam a chave no Redis (`SET NX`); replay da mesma chave retorna o mesmo resultado (`Idempotency-Replayed: true`), payload diferente → `409`, reserva em andamento → `409`.
- **Locking otimista**: `HouseWallet`/carteiras usam `version`; escrita com versão obsoleta retorna `409 CONFLICT` (retry do cliente).
- **Retry transitório**: `WalletService.run()`/`BetService.placeBet()` re-executam a unidade inteira em `CONFLICT` **e** em write-conflict transitório do Mongo (`112`/`TransientTransactionError`), com backoff exponencial + jitter (`src/core/shared/domain/errors/retryTransient.ts`). Validado sob carga (`docs/TESTING-ENV.mdx`).
- **Filas**: operações assíncronas (contato, saque, SIGAP, retenção de auditoria) vão para Bull; falhas são registradas e reprocessadas.
- **Persistência transacional**: Mongo como replica set permite transações (wallet/ledger/bet/treasury) atômicas.
